# Data 目录整理设计

## 背景

当前 `data/` 同时保留了正式数据、可再生中间产物和带版本名的单层目录，增加了理解成本，也使训练与评测脚本依赖过时路径。

## 目标

- 为 `data/`、`teacher_rollouts/`、`sft/`、`eval/`、`rl/` 补充中文 README。
- 删除已经被正式 SFT 数据包含、且能从原始轨迹重新生成的 `sft/v3_json/`。
- 将评测集整理为 `mini / fast / full` 三档并扁平化目录。
- 将唯一一套 RL smoke 数据直接放在 `data/rl/`。
- 同步更新 manifest、脚本默认值和项目文档中的路径。

## 最终结构

```text
data/
├── README.md
├── raw/
├── pool/

│   ├── README.md

    └── manifest.json
```

## 数据保留与删除

- `sft/v3_json/` 的 331 条成功 Teacher 样本已经并入 5817 条正式 SFT 数据；权威原始轨迹仍保存在 `teacher_rollouts/`，因此删除该中间目录。
- `eval/hard_mini_dev_en.jsonl` 改名为 `eval/mini_dev.jsonl`，作为 110 条英文高难度最小评测集。
- 删除过时的 60 条旧 `mini_dev` 和 120 条中英混合 `hard_mini_dev`。
- 保留 `fast_dev` 和 `full_dev`。虽然 fast 是 full 的子集，但它承担低成本中间评测，不属于冗余。
- 将 `rl/smoke_v1_768/` 中的 768 条训练任务、60 条验证任务和 manifest 上移至 `rl/`。README 明确它们是 smoke/repro 数据，而非正式 2048 条 RL 数据。

## 一致性要求

- 更新所有受影响的脚本默认路径和 Markdown 示例。
- 更新 SFT manifest/audit，不再依赖已删除的 `v3_json` 路径。
- 合并 eval 元数据，使新 manifest 只描述保留的三档数据。
- 更新 RL manifest 内部输出路径和验证集来源。
- 最终检查 JSONL 行数、JSON 可解析性、旧路径引用和 Git diff。
