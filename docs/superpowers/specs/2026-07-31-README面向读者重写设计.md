# README 面向读者重写设计

## 目标

将项目自有 README 统一改写为公开用户文档。读者无需了解仓库内部整修过程，也能回答以下问题：

1. 这个项目、目录或脚本集合解决什么问题？
2. 当前应该使用哪些文件和入口？
3. 数据或调用链如何流动？
4. 最小可运行命令是什么？
5. 输入、输出和重要约束分别是什么？

## 受众

- 希望复现数据构造、SFT、评测或 RL 流程的开源用户；
- 希望学习 Agentic RL 项目结构的读者；
- 需要快速定位脚本和数据文件的项目贡献者。

README 不承担内部交接、迁移日志或仓库整修记录的职责。

## 内容边界

### 保留

- XML、repair、协议训练和 Teacher rollout 等具有学习价值的技术演进；
- 当前架构、数据流、文件职责和推荐入口；
- 可直接运行的命令、参数、输入和输出；
- 数据隔离、评测边界、artifact 位置等会影响正确使用的约束；
- 根 README 对技术演进文档的入口。

### 移除或改写

- “已删除”“已清理”“原目录”“曾经放在”等维护记录；
- 本次目录扁平化、文件迁移和 GitHub 清理过程；
- 具体清理日期、旧仓库名兼容和内部交接语气；
- 仅用于解释为什么仓库当前没有某个文件的历史说明。

如果历史事实直接解释当前设计原理，则改写成可复用的技术结论，而不是删除。

## README 统一结构

每份目录 README 根据内容选用以下小节：

1. **用途**：一段话说明目录或模块在主链路中的位置。
2. **结构/文件说明**：说明当前存在的文件和职责。
3. **数据流或工作流**：给出输入、处理过程和输出。
4. **推荐使用方式**：提供可复制的最小命令。
5. **输入与输出**：明确路径、规模、格式和生成位置。
6. **重要约束**：列出数据隔离、许可证、运行产物或评测规则。
7. **进一步阅读**：只链接对用户有学习价值的文档。

## 重点文件

### 根 `README.md`

- 保留项目定位、结果、整体结构、快速开始和技术演进入口；
- 删除只描述内部脚本清理或目录迁移的句子；
- 确保 SFT、评测和 RL 均有可复制命令。

### `data/*/README.md`

- `data/README.md`：给出完整数据链路和各目录入口；
- `raw/`：下载、目录准备、归一化和重建流程；
- `pool/`：任务池结构、过滤规则和重建命令；
- `splits/`：DB-level 划分、数据边界和重建命令；
- `teacher_rollouts/`：候选池、rollout 文件、成功样本转换方式；
- `sft/`：基础集与正式集的关系、文件职责和正式训练入口；
- `eval/`：mini/fast/full 的定位、运行评测和重建方式；
- `rl/`：smoke 数据定位、重建、dry-run 和 Slime 启动入口。

### `sqlite_agent/scripts/*/README.md`

- 按数据、环境、SFT、评测、RL 分类当前脚本入口；
- archive 只说明其用于复现实验或消融，不记录仓库清理过程；
- SFT README 以正式训练和评测工作流为主，技术兼容细节降级为注意事项。

## 验收标准

- 项目自有 README 中不存在本次内部整修过程；
- 每个主要数据目录都包含至少一个明确的使用入口或指向上级使用指南；
- 所有命令使用当前真实路径；
- 不重新引入已删除目录或文件的运行时引用；
- Markdown 链接、JSON/JSONL 路径和脚本入口均存在；
- README 保留足够的技术解释，但语气始终面向公开读者。
